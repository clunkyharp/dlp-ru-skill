# Фаза разработки

Превратите проект в работающий код. Разработка — это то место, где архитектура и контракты становятся конкретной реализацией.

---

## Краткое описание фазы

| Аспект | Детали |
| --- | --- |
| **Цель** | Построить решение в соответствии с проектом |
| **Условия входа** | Утверждённый проект (архитектура, модели данных, контракты) |
| **Условия выхода** | Реализованный и прошедший ревью код, готовый к тестированию |
| **Ключевые артефакты** | Работающий код, задокументированные решения, история коммитов |
| **Шаблоны** | Нет (артефакт — это код) |

---

## Назначение

Разработка отвечает на вопрос: «Как построить то, что спроектировано?»

Без дисциплинированной разработки:

- Код расходится с замыслом проекта
- Несогласованные паттерны создают нагрузку на сопровождение
- Технический долг накапливается быстро
- Интеграция становится болезненной

## Входы и выходы

**Входы:**

- Утверждённый проект (архитектура, модели данных, контракты)
- Среда разработки и инструменты
- Стандарты и соглашения по кодированию

**Выходы:**

- Реализованный и прошедший ревью код
- Задокументированные решения и отклонения
- Код, готовый к тестированию

## Процесс

```mermaid
flowchart LR
    A[Проект] --> B[Настройка]
    B --> C[Реализация]
    C --> D[Ревью]
    D -->|Нужны изменения| C
    D -->|Утверждено| E[Готово к тестированию]
```

Разработка идёт итерациями между реализацией и ревью, пока код не станет соответствовать стандартам.

## Ключевые принципы

- **Следуйте проекту** — реализация должна воплощать проект, а не изобретать его заново
- **Небольшие инкрементальные изменения** — стройте малыми шагами; проверяйте часто
- **Единообразие важнее изощрённости** — предсказуемый код — это поддерживаемый код
- **Оставляйте код лучше, чем нашли** — исправляйте проблемы, когда их видите
- **Документируйте неочевидное** — код показывает «что»; комментарии объясняют «почему»

## Дисциплина разработки

**Перед написанием кода:**

- Тщательно поймите проект
- Правильно настройте среду
- Знайте стандарты кодирования

**Во время написания кода:**

- Реализуйте по одной вещи за раз
- Проверяйте по ходу работы
- Коммитьте часто, с понятными сообщениями

**После написания кода:**

- Сначала просмотрите свою работу сами
- Запросите код-ревью и отреагируйте на него
- Убедитесь, что тесты существуют и проходят

## Чек-лист выхода: когда переходить к тестированию

Выполните ВСЕ пункты, прежде чем переходить к фазе ТЕСТИРОВАНИЯ:

- [ ] Реализация завершена согласно проекту
- [ ] Код-ревью одобрено
- [ ] Код проходит автоматические проверки (линтинг, статический анализ)
- [ ] Тестирование разработчиком завершено
- [ ] Не осталось известных нерешённых проблем

Если какой-либо пункт списка не выполнен, продолжайте работу по разработке.

Разработка продолжает пересекаться с тестированием: реализации проверяются по мере создания.

## Сквозные аспекты для учёта

При разработке учитывайте:

- **Безопасность** (`concerns/security.md`) — следуйте практикам безопасного кодирования, проверяйте ввод, кодируйте вывод
- **Производительность** (`concerns/performance.md`) — реализуйте эффективно, избегайте преждевременной оптимизации
- **Доступность** (`concerns/accessibility.md`) — реализуйте доступные компоненты интерфейса
- **Наблюдаемость** (`concerns/observability.md`) — добавляйте логирование, метрики и трассировку
