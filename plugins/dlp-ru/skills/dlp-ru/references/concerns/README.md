# Сквозные аспекты

В этой папке собраны рекомендации по аспектам, которые охватывают все фазы разработки. В отличие от документов, привязанных к фазам, они применимы на протяжении всего жизненного цикла разработки ПО.

## Матрица интеграции с фазами

Обращайтесь к этим аспектам на каждой фазе:

### Фаза ТРЕБОВАНИЙ

| Аспект | Действия |
| --- | --- |
| **Безопасность** | Определить чувствительные данные, требования к аутентификации, нужды соответствия нормам (GDPR, PCI, HIPAA) |
| **Производительность** | Определить цели по времени ответа, ожидаемую пропускную способность, требования к масштабируемости |
| **Доступность** | Определить потребности пользователей в доступности, требуемое соответствие (уровень WCAG) |
| **Наблюдаемость** | Определить требования к мониторингу, потребности в оповещениях, требования к аудиторскому логированию |

### Фаза ПРОЕКТИРОВАНИЯ

| Аспект | Действия |
| --- | --- |
| **Безопасность** | Установить границы доверия, спроектировать аутентификацию/авторизацию, спланировать шифрование, создать модель угроз |
| **Производительность** | Проектировать для эффективности, выявить потенциальные узкие места, спланировать стратегию кэширования |
| **Доступность** | Проектировать инклюзивные интерфейсы, спланировать навигацию с клавиатуры, обеспечить цветовой контраст |
| **Наблюдаемость** | Спроектировать стратегию логирования, определить метрики, спланировать распределённую трассировку |

### Фаза РАЗРАБОТКИ

| Аспект | Действия |
| --- | --- |
| **Безопасность** | Валидировать весь ввод, кодировать вывод, использовать параметризованные запросы, следовать практикам безопасного кодирования |
| **Производительность** | Реализовывать эффективно, избегать N+1 запросов, использовать подходящие структуры данных |
| **Доступность** | Использовать семантический HTML, добавлять ARIA-метки, обеспечивать управление фокусом |
| **Наблюдаемость** | Добавлять структурированное логирование, отправлять метрики, передавать контекст трассировки |

### Фаза ТЕСТИРОВАНИЯ

| Аспект | Действия |
| --- | --- |
| **Безопасность** | Тестировать обход аутентификации, авторизацию на каждой конечной точке, атаки внедрением |
| **Производительность** | Нагрузочно тестировать критичные пути, проверять время ответа, тестировать под стрессом |
| **Доступность** | Тестировать со скринридерами, проверять навигацию с клавиатуры, проверять цветовой контраст |
| **Наблюдаемость** | Проверять, что логи содержат ожидаемые данные, тестировать оповещения, валидировать метрики |

---

## Как использовать

1. **При каждом переходе между фазами** просматривайте соответствующую строку матрицы интеграции
2. **При принятии решений** проверяйте, есть ли в аспектах релевантные рекомендации
3. **Перед завершением фазы** убедитесь, что требования, связанные с аспектами, учтены
4. **Во время код-ревью** проверяйте, что соблюдаются практики, специфичные для аспектов

## Когда приоритизировать аспекты

Не все аспекты одинаково важны для каждого проекта. Расставляйте приоритеты исходя из контекста:

**Проекты, критичные к безопасности:**

- Финансовые системы, здравоохранение, сервисы аутентификации
- Безопасность не обсуждается; остальные аспекты подстраиваются под неё

**Проекты, критичные к производительности:**

- Системы реального времени, высоконагруженные приложения, игры
- Требования к производительности определяют архитектурные решения

**Проекты, критичные к доступности:**

- Государственные услуги, публичные приложения, образовательные инструменты
- Доступность может быть юридически обязательной и этически важна

**Проекты, критичные к наблюдаемости:**

- Распределённые системы, микросервисы, продакшен-системы
- Понимание поведения системы в продакшене необходимо

Когда аспекты конфликтуют, явно документируйте компромисс с помощью `templates/design-decision.md`.
