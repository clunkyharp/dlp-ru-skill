# Доступность

Доступность (accessibility) гарантирует, что ПО пригодно для людей с разными возможностями. Это включает пользователей с нарушениями зрения, слуха, моторики или когнитивными нарушениями, а также тех, кто пользуется вспомогательными технологиями.

---

## Образ мышления в доступности

### Универсальный дизайн

Проектируйте для максимально широкого круга пользователей с самого начала, а не задним числом.

### Постоянные, временные, ситуативные ограничения

Ограничения возможностей образуют спектр:

| Тип | Постоянное | Временное | Ситуативное |
| --- | --- | --- | --- |
| Зрение | Слепота | Инфекция глаза | Яркое солнце |
| Слух | Глухота | Инфекция уха | Шумная обстановка |
| Моторика | Отсутствие конечности | Сломанная рука | Ребёнок на руках |
| Когнитивные | Трудности в обучении | Сотрясение мозга | Отвлечение |

Доступный дизайн помогает всем, а не только людям с постоянными ограничениями.

### Вспомогательные технологии

Пользователи взаимодействуют с ПО с помощью различных инструментов:

- **Скринридеры** — зачитывают содержимое вслух (JAWS, NVDA, VoiceOver)
- **Экранные лупы** — увеличивают части экрана
- **Голосовое управление** — навигация и ввод с помощью речи
- **Переключатели (switch devices)** — отдельные кнопки для пользователей с ограниченной подвижностью
- **Брайлевские дисплеи** — тактильный вывод для слепых пользователей

ПО должно работать с этими инструментами, а не против них.

## Основные принципы (POUR)

### Воспринимаемость (Perceivable)

Информация должна быть представлена способами, которые пользователи могут воспринять.

**Текстовые альтернативы** — у нетекстового содержимого есть текстовые эквиваленты.

Изображения:

```text
<img src="chart.png" alt="Sales increased 25% in Q3">
```

Иконки:

```html
<button aria-label="Close dialog">×</button>
```

Декоративные изображения:

```text
<img src="divider.png" alt="" role="presentation">
```

**Субтитры и расшифровки** — у аудио и видео есть текстовые альтернативы.

Видеоконтенту нужны:

- Субтитры для диалогов и звуков
- Аудиоописание визуальной информации
- Расшифровка (транскрипт) для доступа к полному тексту

**Адаптируемая подача** — содержимое можно представить по-разному без потери смысла.

Хорошо:

- Используйте семантический HTML (заголовки, списки, таблицы)
- Содержимое имеет смысл без стилей

Плохо:

- Смысл передаётся только цветом
- Порядок содержимого зависит от вёрстки

**Различимость (Distinguishable)** — содержимое легко увидеть и услышать.

Цветовой контраст:

- Обычный текст: минимальное соотношение 4.5:1
- Крупный текст (18pt+): минимальное соотношение 3:1
- Компоненты интерфейса: минимальное соотношение 3:1

Не полагайтесь только на цвет: Плохо: «Обязательные поля выделены красным» Лучше: «Обязательные поля отмечены знаком *»

### Управляемость (Operable)

Все пользователи должны иметь возможность управлять компонентами интерфейса.

**Доступность с клавиатуры** — вся функциональность доступна с клавиатуры.

Требования:

- Все интерактивные элементы получают фокус
- Логичный порядок табуляции
- Нет «ловушек» клавиатуры
- Видимый индикатор фокуса

Проверка:

- Можно ли выполнить все задачи, используя только Tab, Enter, Space и стрелки?

**Навигируемость (Navigable)** — пользователи могут найти содержимое и понимают, где находятся.

Структура страницы:

- Описательные заголовки страниц
- Чёткая иерархия заголовков (h1 → h2 → h3)
- Ссылки быстрого перехода к основному содержимому (skip links)
- Несколько способов найти страницы (навигация, поиск, карта сайта)

Управление фокусом:

- Логичный порядок фокуса
- Фокус всегда виден
- Фокус корректно перемещается в динамическом содержимом

### Понятность (Understandable)

Информация и работа интерфейса должны быть понятны.

**Читаемость** — текстовое содержимое читаемо и понятно.

Язык:

- Объявляйте язык страницы (<html lang="en">)
- Отмечайте смену языка в содержимом
- Определяйте необычные слова или аббревиатуры

Ясность:

- Используйте простой язык
- Делайте предложения краткими
- Объясняйте жаргон и аббревиатуры

**Предсказуемость** — страницы ведут себя предсказуемо.

Согласованность:

- Навигация расположена в одном месте на всех страницах
- Похожие компоненты ведут себя одинаково
- Нет неожиданных смен контекста

Смены контекста:

- Не меняйте контекст только из-за получения фокуса
- Предупреждайте перед открытием новых окон
- Объясняйте результаты отправки форм

**Помощь при вводе** — помогайте пользователям избегать и исправлять ошибки.

Обработка ошибок:

- Чётко указывайте ошибки
- Описывайте ошибки текстом (а не только цветом)
- Предлагайте исправления
- Позволяйте проверить данные перед окончательной отправкой

Метки и инструкции:

- Подписывайте все поля форм
- Давайте примеры формата
- Чётко отмечайте обязательные поля

### Надёжность (Robust)

Содержимое должно работать с текущими и будущими технологиями.

**Совместимость** — работает со вспомогательными технологиями.

Корректная разметка:

- Полные открывающие и закрывающие теги
- Нет дублирующихся атрибутов
- Уникальные ID

Использование ARIA:

- По возможности используйте нативные HTML-элементы
- Добавляйте ARIA, только когда HTML недостаточно
- Убедитесь, что роли, состояния и свойства ARIA корректны

## Рекомендации по реализации

### Семантический HTML

Используйте HTML-элементы по их прямому назначению.

Плохо:

```html
<div class="button" onclick="submit()">Submit</div>
<div class="heading">Page Title</div>
```

Лучше:

```html
<button type="submit">Submit</button>
<h1>Page Title</h1>
```

**Типичные семантические элементы:**

| Назначение | Элемент |
| --- | --- |
| Области страницы | header, nav, main, footer, aside |
| Заголовки | h1-h6 (по порядку) |
| Списки | ul, ol, li |
| Таблицы | table, th, td (с scope) |
| Формы | form, label, fieldset, legend |
| Кнопки | button |
| Ссылки | a (с href) |

### Формы

Формы критичны для доступности.

Связь меток с полями:

```html
<label for="email">Email</label>
<input type="email" id="email" name="email">
```

Обязательные поля:

```html
<label for="name">Name (required)</label>
<input type="text" id="name" required aria-required="true">
```

Сообщения об ошибках:

```html
<input type="email" id="email" aria-describedby="email-error">
<span id="email-error" role="alert">Please enter a valid email</span>
```

Группировка связанных полей:

```html
<fieldset>
  <legend>Shipping Address</legend>
  <!-- address fields -->
</fieldset>
```

### Изображения

Всем изображениям нужны подходящие текстовые альтернативы.

Информативные изображения:

```text
<img src="graph.png" alt="Revenue grew from $1M to $1.5M in 2024">
```

Функциональные изображения (ссылки/кнопки):

```html
<a href="/home">
  <img src="logo.png" alt="Company Name - Home">
</a>
```

Декоративные изображения:

```text
<img src="decorative-border.png" alt="" role="presentation">
```

Сложные изображения:

```html
<figure>
  <img src="complex-diagram.png" alt="System architecture overview">
  <figcaption>
    Detailed description: The system consists of...
  </figcaption>
</figure>
```

### Динамическое содержимое

Одностраничные приложения и динамические обновления требуют особого внимания.

Управление фокусом:

```text
// После загрузки нового содержимого
newContent.focus()

// После закрытия модального окна
triggerButton.focus()
```

Живые области (live regions, озвучивание изменений):

```html
<div aria-live="polite">
  3 items in cart
</div>

<div role="alert">
  Error: Payment failed
</div>
```

Состояния загрузки:

```html
<button aria-busy="true" aria-label="Submitting...">
  <span class="spinner"></span>
</button>
```

### Взаимодействие с помощью клавиатуры

Стандартные клавиатурные паттерны, которых ожидают пользователи:

| Элемент | Клавиша | Действие |
| --- | --- | --- |
| Кнопка | Enter, Space | Активировать |
| Ссылка | Enter | Перейти по ссылке |
| Чекбокс | Space | Переключить |
| Радиокнопки | Стрелки | Переместить выбор |
| Вкладки | Стрелки | Переключить вкладку |
| Меню | Стрелки | Навигация по пунктам |
| Диалог | Escape | Закрыть |

Пользовательские компоненты должны реализовывать ожидаемые паттерны:

Пример панели вкладок:

- Вкладка: `aria-selected="true/false"`
- Панель: `aria-labelledby="tab-id"`
- Стрелки перемещают между вкладками
- Содержимое вкладки получает фокус

## Тестирование доступности

### Автоматизированное тестирование

Инструменты автоматически находят около 30% проблем.

- axe DevTools (расширение браузера)
- WAVE (расширение браузера)
- Lighthouse (встроен в Chrome)
- Pa11y (командная строка)
- jest-axe (модульное тестирование)

Автоматизированные тесты ловят:

- Отсутствующий alt-текст
- Проблемы цветового контраста
- Отсутствующие метки форм
- Некорректный ARIA
- Проблемы порядка заголовков

### Ручное тестирование

Необходимо для полного покрытия.

**Тестирование с клавиатуры:**

1. Отключите мышь
2. Пройдите по всей странице с помощью Tab
3. Активируйте все элементы управления клавишами Enter/Space
4. Проверьте видимость фокуса на всём протяжении
5. Убедитесь, что нет клавиатурных ловушек

**Тестирование со скринридером:**

Тестируйте как минимум с одним:

- NVDA (Windows, бесплатный)
- VoiceOver (macOS/iOS, встроенный)
- TalkBack (Android, встроенный)

Проверьте:

- Всё содержимое озвучивается
- У изображений есть описания
- Формы подписаны
- Динамические обновления озвучиваются
- Навигация имеет смысл

**Тестирование масштабирования:**

1. Увеличьте до 200%
2. Проверьте, что содержимое перестраивается (нет горизонтальной прокрутки)
3. Убедитесь, что всё содержимое видно
4. Проверьте, что области касания остаются удобными для использования

### Чек-лист проверки доступности

Воспринимаемость:

- [ ] У изображений есть alt-текст
- [ ] У видео есть субтитры
- [ ] Цветовой контраст соответствует минимумам
- [ ] Цвет — не единственный индикатор
- [ ] Содержимое работает без стилей

Управляемость:

- [ ] Все функции доступны с клавиатуры
- [ ] Порядок фокуса логичен
- [ ] Индикатор фокуса виден
- [ ] Нет клавиатурных ловушек
- [ ] Есть ссылка быстрого перехода к основному содержимому

Понятность:

- [ ] Язык страницы объявлен
- [ ] Заголовки иерархичны
- [ ] Поля форм подписаны
- [ ] Ошибки чётко обозначены
- [ ] Инструкции предоставлены

Надёжность:

- [ ] HTML валиден
- [ ] ARIA используется корректно
- [ ] Работает со скринридерами
- [ ] Динамическое содержимое доступно
