## Когда создавать каждый артефакт

### Фаза ТРЕБОВАНИЙ

| Шаблон | Создавать, когда |
| --- | --- |
| `requirements-specification.md` | Всегда — основной результат работы над требованиями |
| `user-stories.md` | Когда требования фиксируются с точки зрения пользователя |

### Фаза ПРОЕКТИРОВАНИЯ

| Шаблон | Создавать, когда |
| --- | --- |
| `design-decision.md` | Для каждого значимого проектного выбора с альтернативами |
| `architecture.md` | Для новых систем или крупных архитектурных изменений |
| `data-model.md` | При определении структур данных и связей |
| `api-contract.yml` | Когда система предоставляет API (REST, GraphQL и т. д.) |

## Инструкции по использованию

### Шаг 1: Скопируйте шаблон

Скопируйте нужный шаблон в каталог документации вашего проекта:

```text
project/
├── docs/                          ← Ваш каталог документации
│   ├── requirements.md            ← Скопировано из templates/requirements-specification.md
│   ├── architecture.md            ← Скопировано из templates/architecture.md
│   └── decisions/                 ← Проектные решения
│       └── 001-database-choice.md ← Скопировано из templates/design-decision.md
```

### Шаг 2: Замените заполнители

Шаблоны содержат заполнители в `[квадратных скобках]` и маркеры `TODO`:

- `[Project Name]` → замените названием вашего проекта
- `[Description]` → замените реальным описанием
- `TODO: ...` → заполните указанный раздел

### Шаг 3: Адаптируйте под свои нужды

Шаблоны — это отправные точки. Изменяйте их по мере необходимости:

- Удаляйте разделы, которые не применимы
- Добавляйте разделы, которые нужны вашему проекту
- Подстраивайте форматирование под соглашения проекта

## Форматы шаблонов

### Шаблоны Markdown (.md)

Большинство шаблонов используют Markdown для максимальной совместимости:

- Читаемы человеком
- Удобны для систем контроля версий
- Отображаются в большинстве инструментов

### Шаблон OpenAPI (.yml)

Шаблон контракта API использует формат OpenAPI 3.1 YAML:

- Отраслевой стандарт спецификации API
- Машиночитаем, подходит для генерации кода
- Поддерживается многими инструментами (Swagger, Postman и др.)

## Создание новых шаблонов

Если вам нужен тип артефакта, не охваченный существующими шаблонами:

1. Следуйте структуре существующих шаблонов
2. Включайте чёткие заголовки разделов
3. Используйте заполнители единообразно (`[скобки]` для обязательного, `TODO` для заметок)
4. Добавьте вверху краткое описание назначения шаблона

---

## Чек-лист качества шаблона

Хорошие шаблоны:

- [ ] Имеют чётко указанное вверху назначение
- [ ] Используют единый формат заполнителей
- [ ] Включают все необходимые разделы
- [ ] Не содержат лишних разделов
- [ ] Легко заполняются
- [ ] Дают полезную документацию после заполнения
