# Основы (Foundations)

В этой папке собраны базовые понятия и мета-руководство, на которых держится весь протокол разработки. Документы задают общий словарь, принципы и подходы, на которые ссылаются все последующие фазы.

---

## Краткая справка

| Документ | Назначение | Когда читать |
| --- | --- | --- |
| [terminology.md](terminology.md) | Глоссарий терминов | Термин непонятен или использован неожиданно |
| [principles.md](principles.md) | Базовые принципы разработки | При принятии проектных и реализационных решений |
| [decision-making.md](decision-making.md) | Подход к выбору | При компромиссах или конфликте принципов |
| [work-paths.md](work-paths.md) | Стандартный и Минимальный пути | Чтобы определить уровень формальности для задачи |

---

## Назначение

Прежде чем переходить к конкретным фазам, таким как сбор требований или реализация, нужен общий фундамент:

- **Общий язык** — термины означают одно и то же везде в протоколе
- **Руководящие принципы** — базовые убеждения, на которых строится каждое решение
- **Подходы к решениям** — как выбирать, когда приходится идти на компромиссы

## Порядок чтения

Прочитайте документы по порядку, прежде чем переходить к любой фазе:

1. **terminology.md** — задаёт словарь
2. **principles.md** — задаёт ценности
3. **decision-making.md** — готовит к ситуациям компромисса
4. **work-paths.md** — определяет уместный уровень формальности

## Как пользоваться этой папкой

**Для LLM-агентов:**

1. Прочитайте эти документы в первой сессии работы с протоколом
2. Обращайтесь к `terminology.md`, когда встречаете незнакомый термин
3. Обращайтесь к `principles.md` при принятии решений
4. Обращайтесь к `decision-making.md`, когда принципы конфликтуют
5. Обращайтесь к `work-paths.md`, чтобы выбрать Стандартный или Минимальный путь для каждой задачи

**Для людей:**

1. Прочитайте все четыре документа до начала любой фазы
2. Возвращайтесь к ним как к справочнику на протяжении проекта

## Краткое резюме ключевых принципов

Для быстрой справки, основные принципы:

| Принцип | Смысл |
| --- | --- |
| **YAGNI** | Не создавайте функциональность, пока она реально не понадобилась |
| **KISS** | Выбирайте самое простое решение, которое работает |
| **DRY** | У каждого знания есть одно авторитетное место |
| **Разделение ответственности** | Каждый компонент отвечает за одну чётко определённую задачу |
| **Fail Fast, Fail Clearly** | Обнаруживайте и сообщайте об ошибках рано, с понятными сообщениями |
| **Композиция вместо наследования** | Собирайте объекты из небольших частей, а не из глубоких иерархий |
| **Закон Деметры** | Общайтесь только с ближайшими «друзьями», а не с «посторонними» |

Полные объяснения и случаи, когда принцип применять или нарушать, смотрите в [principles.md](principles.md).
